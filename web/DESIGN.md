# 设计说明

## 定位

这是企业证据检索控制台，不是聊天界面。页面要回答的第一件事是“这条依据出自哪里”，而不是“模型说了什么”。所以每条结果的第一行是引用身份（文档、版本、条款、页码），第二层是被引用的原文，最后才是分数。分数是仪器读数，不是可信度标签。

## 令牌

颜色只有七个，全部在 `src/styles/tokens.css`：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#E8EAE4` | 页面底色，冷灰绿纸面 |
| `--ink` | `#15191A` | 主文字、按钮、引用左边线 |
| `--stamp` | `#A3222A` | **只**用于拒答与“未命中”状态 |
| `--steel` | `#5A6B6C` | 次要文字、标签、图标 |
| `--rule` | `#C3CBC4` | 1px 分隔线、输入框边、骨架 |
| `--verified` | `#2C5545` | 命中、正常状态、上传成功 |
| `--surface` | `#F1F2EE` | 输入框/表头底、引用块底 |

没有第八种颜色。层级靠字重、字号、留白、1px 规则线与同一色板内的透明度建立。`--stamp` 不参与 hover、不参与错误面板、不参与删除确认；错误与删除使用 `--ink` / `--steel`，避免把“拒答”和“系统故障”混为一谈。

## 字体

通过 npm 安装 `@fontsource/*`，构建时把 woff/woff2 打进 `dist/assets`，运行时没有任何外网字体请求：

| 字体 | 字重 | 角色 |
|---|---|---|
| Archivo | 600 / 700 | 标题、文档名、页面字标，紧字距（-0.02em ~ -0.035em） |
| IBM Plex Sans | 400 / 500 | 正文、按钮、表单 |
| IBM Plex Serif | 400 | **引用原文**，行高 1.75 |
| IBM Plex Mono | 400 / 500 | 分数、页码、诊断表、路径 |

CJK 使用系统回退：正文 `Microsoft YaHei / PingFang SC`，引用原文 `Songti SC / SimSun`。`@fontsource` 不含 CJK 字形；没有把中文做成网络字体，既是为了离线，也是因为中文宋体回退恰好符合“原始文档”的语境。

数字一律 `font-variant-numeric: tabular-nums`（`.mono` / `.num`），避免分数变化时列宽跳动。

## 布局

- 页头：字标 + 三个导航，底部 1px 实线收口；active 用 2px 下划线，不用胶囊。
- 检索页：320px 粘性左栏 + 右栏结果；正文与引用块限宽 `72ch`；桌面左栏顶部 `96px`。
- 900px 以下折为单栏（早于 brief 的 768px 上限，避免 769–900px 时结果列被挤到 350px 以下）；≤768 的验收宽度一定是单栏。
- 文档库：页头、上传带、表格三层，之间只有 1px 规则线；表格在 ≤768px 转为带标签的块状行，360px 不横向滚动。
- 关于页：一张“标定单”，左侧 156px 标签列 + 右侧内容列，用规则线分节。

没有卡片、没有 `border-radius`（仅 0）、没有 `box-shadow`、没有渐变。结果之间只隔一条 1px 线；引用块用 2px 左线和 `--surface` 底，而不是圆角卡片。

## 引用作为视觉对象

每条结果的标题不是“卡片标题”，而是引用身份本身：

```
《文档标题》v2025 · 4.2.1 诊断标准 · 第 4 页
docKey  生效 2025-01-01
┌ 引用原文（IBM Plex Serif，72ch，1.75 行高）
└ …
RRF 0.0328    重排 0.2685                    复制引用
```

结果序号在左侧 38px 窄栏里，用等宽数字；它是必要的排名信息，不是装饰编号。分数只以等宽数字出现：`RRF` 是原始融合名次分，`重排` 是绝对信号加权和，两者量纲不同，所以结果头明确写“按重排分排序”，并在同一行说明不能直接比较。

命中词高亮不经过 `v-html`：`src/lib/highlight.ts` 先把查询拆成词项，再在文本上计算区间，最后渲染成文本节点 + `<mark>`。服务端内容永远不会被当成 HTML 解析。

## 动效

只保留两处：

1. 结果首次出现时按 40ms 间距依次淡入（`ResultItem` 的 `animation-delay`）。
2. 拒答区块用 `clip-path` 从上向下展开，说明“这是一次判定结果”。

加载态是与结果同形的静态骨架屏，不是 spinner；没有 shimmer、没有 hover 抬升、没有逐卡片入场。上传进度条不做过过渡，直接反映 XHR 的进度。`prefers-reduced-motion: reduce` 下全局关闭 animation / transition。

## 被砍掉的装饰（Chanel 原则）

砍掉了“每条结果一个分数条形图/小仪表盘”。它看起来很“数据可视化”，但 RRF 是 0.016~0.033 的名次分，重排分是不同量纲的加权和，画成同一根 0~1 的条会暗示“这是概率”，属于错误信息。于是每条结果只留等宽数字，把唯一的图形读数留给拒答诊断里的候选余弦分布：那里有真实阈值（0.55 / 0.63）和候选点，图形回答了“为什么拒答”，而不是装饰结果。

## 文案

- 动词开头：`检索`、`上传并切分`、`确认删除`、`重试检索`。
- 说明后果：上传说明会写入片段；删除说明不可恢复；拒答说明“为什么不给结果”和下一步。
- 数字诚实：关于页只列 40 条 QA 的实测值，并写明“1 题 = 2.86pp，所以不宣称高准确率”。证据路径以相对文本列出，不做外链。

## 无障碍

- 全局 `:focus-visible` 2px `--ink` 轮廓；按钮、输入、range、文件选择都可见。
- 表单都有 `label`；拒答/结果区 `aria-live="polite"`；复制成功/删除结果通过 live region 播报。
- 颜色对比：`--ink` / `--paper`、`--steel` / `--paper`（4.6:1）、`--verified` / `--paper`、`--stamp` / `--paper` 均达到 AA 正文要求；`--rule` 只用于非文字分隔。
- 360px 宽：检索页单栏、结果引用块换行、文档表格转为块状行，无横向滚动。
